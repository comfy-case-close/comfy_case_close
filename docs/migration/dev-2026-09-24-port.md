# Latest `dev` integration into phase-1 cashclose

This merge incorporates `origin/dev` through `3c6bac9` into
`feat/phase1-cashclose-endpoints`. The split-service SQL DDL and entities remain
authoritative. The old `comfy-case-close-app` and `database-migration` trees are
not runtime modules in this branch.

| Latest `dev` change | Phase-1 disposition |
|---|---|
| STAFF can call carry-forward | No carry-forward endpoint: the new DDL has no opening/final drawer balance or carried sales. Existing staff permissions govern the supported close flow. |
| One-shot `PUT /cash-closes/{id}` after submit/approval, including edit diffs | Replaced by DRAFT-only `PATCH /cash-closes/{id}`, denomination and movement endpoints, reopen where permitted, and immutable decisions. The new DDL forbids edits to APPROVED closes. |
| Per-category approval and explanation/tip tables | Replaced by `cash_movement` lines with per-line decisions and append-only movement history. |
| Tip-jar payouts | Initially ported as a tenant-scoped ledger. Superseded by migration `007-cashclose-006-shift-tips`: drawer and jar cash are counted together, tips use the `TIPS` movement kind, `GET /api/v1/tips` gives shift totals, and the payout ledger/API are removed. |
| Fund withdrawals | Replaced period reconciliation with attributed transfers, confirmation, and revision history. See [withdrawal confirmation](fund-withdrawal-confirmation.md) for current endpoints, migration, and the retained non-blocking amount threshold warning. |
| Private GCS attachments and signed URLs | Moved into files-service, which owns bytes and `files.stored_file`. `POST /api/v1/files/cash-close-attachments` uploads a private object and returns `fileId`; `GET /api/v1/files/{fileId}/view-url` returns a short-lived signed link. Both require `X-Branch-Id` and live branch permissions. Cashclose then links the `fileId` through its existing attachment endpoint. |
| Report tip split | `CashCloseResponse` exposes only `tipsTotal`; drawer and jar cash are counted together. |
| Date, withdrawal and denomination checks | Future business dates and negative derived cash remaining are rejected. The existing denomination replacement endpoint already checks unique, non-negative whole-note quantities and active face values. |
| Old `app_config` column, `tip_payouts` table and Liquibase XML | Replaced by one additive SQL changeset in this branch's master changelog. The prior schemas/IDs would conflict with the current UUID, RLS, and config model. |
| `1.0.0.11-user-positions.xml` rename and generated flattened POMs | Not copied. Position/permission migrations and Maven reactor remain those of this branch. |

The old unpaid-bill repayment proof condition is not applied to the current
`UNPAID_BILL` movement kind: this kind records that a customer **has not yet
paid**, and requiring a repayment photo at that moment would make it unusable.
Receipts continue to be enforced by each movement kind's `requires_receipt`
flag. The old attachment deletion API is also not added because uploaded files
are immutable, may be referenced by more than one record, and need a separate
reference-aware retention policy.

The GCS key stays outside the repository. Configure files-service with
`GCS_ENABLED`, `GCS_BUCKET_NAME`, and `GCS_SERVICE_ACCOUNT_KEY` (absolute mounted
file path), plus optional prefix, maximum size, and signed URL lifetime. The
bucket must stay private. A staged deployment must apply the new SQL changeset
before starting cashclose-service with schema validation; do not point tests at
the production database.
